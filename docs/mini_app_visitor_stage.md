# MA-3: рабочий интерфейс посетителя и localhost-просмотр

11.10.2026, ветка dev. Статус: в работе, локальный просмотр готов. Пользователь разрешил продолжить без тестового бота и HTTPS, по примеру урока. Реальная авторизация MA-2 остаётся открытой.

## Просмотр владельцем

[Открыть приложение](http://127.0.0.1:8766/app/). Сервер привязан только к этому компьютеру. В панели сверху доступны первое посещение, повторный посетитель, отсутствие доступа, ожидание допуска и блокировка; ширины 320/360/390/430 px. В шапке переключается тема. Это работающие формы/API с отдельной SQLite, а не статическая картинка. Использовать только вымышленные контакты: реальные сообщения Telegram, Google-события и email не отправляются.

1. Начать запись, выбрать формат, длительность, связь, день и время.
2. Проверить возврат назад; заполнить вымышленные контакты и цель, отметить согласие.
3. Проверить итог, подать заявку, открыть её в «Мои заявки».
4. В сценарии повторного посетителя посмотреть три группы заявок и сохранённые данные.
5. Сообщить замечания к читаемости и шагам. Административный интерфейс относится к MA-4.

## Реализация и границы

- mini_app/: React 19.3.0, TypeScript 6.0.3, Vite 8.3.4; pnpm 11.25.0, версии и зависимости зафиксированы lock-файлом. Типы DTO генерируются из OpenAPI. Production UI получает Telegram initData, сессия хранится только в памяти; местный вход доступен исключительно в отдельном local_preview.py.
- PATCH /api/v1/me/draft сохраняет полный выбор до hold с CAS revision. DELETE /api/v1/me/draft с confirmed=true сбрасывает общий черновик и освобождает hold. После hold изменение параметров требует явного освобождения времени. Контакты сохраняются последовательно после выхода из валидного поля. Потерянный ответ команды повторяется с прежним Idempotency-Key.
- GET /api/v1/me/bookings?group=review|upcoming|history фильтрует до пагинации; курсор связан с фильтрами. Review включает attention; confirmed становится историей после ends_at. Карточка и отмена авторизуются на сервере.
- Только существующие DraftStore/Commands/BookingService определяют бронирование, согласия и права. Миграций сверх локальной схемы v10 этапа MA-2 нет.
- local_preview.py использует фиксированные вымышленные ID, отдельную базу .secrets/miniapp-preview/test.sqlite, синтетический ключ в памяти и календарный адаптер без сетевого I/O. Рабочий .env не читается. Host/Origin/адрес клиента ограничены loopback, чужие Origin и cross-site запросы отклоняются. Production factory не содержит /local-preview/session; devTelegramId из URL не авторизует пользователя.
- В preview общий worker обрабатывает только тестовые таймеры/отмены; очередь внешней доставки не запускается. Подтверждённые демонстрационные встречи содержат тестовую ссылку. Не использовать её как настоящий созвон.

Автоматические проверки: tests/test_mini_app_visitor_stage.py — выбор/CAS/сброс, запрет изменения live hold, изоляция preview, подмена ID/Host/Origin, доступ четырёх ролей, серверные группы. mini_app/tests/visitor.test.mjs — Москва/граница дня, контакты, смена группы по ends_at, повтор команды после потерянного ответа, очистка bearer при 401. Полный итог регрессии записывается ниже после завершения прогона.

Не проверены: настоящие initData/WebView, экранная клавиатура и safe area на Android/iOS, реальные Google/email/Telegram и cross-channel поведение на VPS. Просмотр владельцем ещё не получен. Эти пункты не считаются закрытыми локальным preview.

Для разработки Vite: pnpm dev (127.0.0.1:5173/app/), backend остаётся 8766. Сборка обязательна для статического просмотра. Проверка контракта: python scripts/export_mini_app_contract.py --check и node scripts/generate_mini_app_types.mjs --check. CI dev дополнен отдельной сборкой/тестами frontend, без deploy. Main, VPS, рабочая база и .env не изменялись. Изменения MA-1/MA-2/MA-3 пока находятся в рабочей копии dev; commit/push не выполнялись.

Итог локальных проверок: полный Python-прогон — 173 случая, 172 успешных, 1 пропущен (POSIX-права в Windows; проверяются CI), 1 прежнее предупреждение Starlette TestClient/httpx.
