## Где хранится реализация

| Часть | Файлы / место |
|---|---|
| Бизнес-правила слотов и записи | `src/meeting_bot/rules.py`, `service.py`, `calendar_flow.py` |
| SQLite и миграции | `src/meeting_bot/database.py`, `src/meeting_bot/migrations/` |
| Диалоги посетителя и администратора | `src/meeting_bot/visitor_flow.py`, `admin_flow.py` |
| Telegram-интерфейс и уведомления | `src/meeting_bot/telegram_app.py`, `telegram_transport.py`, `notification_delivery.py` |
| Google Calendar и OAuth | `src/meeting_bot/google_calendar.py`, `google_auth.py` |
| Фоновые задания и безопасные логи | `src/meeting_bot/worker.py`, `technical_log.py` |
| Настройки | `.env.example` показывает имена переменных; реальные ключи и токены только в игнорируемом Git файле `.env` локально и в `/opt/meeting-bot/.env` на VPS. Значения не копировать в ТЗ, Git, тесты или журналы. |
| Данные и логи | Локально: игнорируемые Git `data/`, `logs/`. На VPS: `/opt/meeting-bot/data/bot.sqlite`, `/opt/meeting-bot/logs/`. |
| Развёртывание и публичная страница | `Dockerfile`, `compose.yaml`, `deploy/`, `public_site/`. Работающий бот и фоновый процесс — два контейнера одного проекта на российском VPS. `https://meetcalendar.fin-partner.pro/` сейчас показывает страницу бота и политику; это **не** Mini App. |
| Проверки и обновления | `tests/`, `.github/workflows/ci.yml` для `main`, `.github/workflows/dev-ci.yml` для `dev`, `scripts/auto_deploy.py`. VPS автоматически обновляет код контейнеров только из проверенной ветки `main`, не из `dev`. |

## Что запросить в новом диалоге

> Подготовь отдельное техническое задание для Telegram Mini App как дополнения к работающему @MyMeetPlanning_bot. Сохрани существующий чат-бот, его SQLite-базу, правила записи, Google Calendar и уведомления; Mini App должен предоставлять аналогичные действия посетителя и администратора через интерфейс, используя общие правила и данные, без второй независимой логики бронирования. Сначала изучи три основных документа и существующий код по карте выше. Опиши сценарии, различия интерфейсов, безопасную Telegram-аутентификацию, доступ к данным через API, защиту от двойной записи, обработку ошибок, персональные данные, совместимость, миграции, развёртывание и критерии приёмки. Укажи решения, которые требуют моего согласования; не считай фронтенд-фреймворк и технологию API уже утверждёнными. Пока готовь только ТЗ: не меняй работающего бота и VPS. Все новые файлы и commit направляй в `dev`; `main` и рабочий сервер обновлять только после отдельного согласования.
