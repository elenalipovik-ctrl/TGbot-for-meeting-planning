## Как это сделано в уроке

В транскрибации, часть 3 «Деплой», строки 616–725: автор завершает интеграцию, использует прежний домен и сервер бота, переносит изменения из dev в main, выполняет серверное размещение и проверку, затем указывает выданный URL в BotFather Main App и меню. Самостоятельная новая платформа размещения не требуется: приложение работает на существующем сервере, Telegram открывает его HTTPS-страницу. Упоминание main в уроке не даёт разрешения менять main этого проекта.

## Рекомендуемый адрес и устройство

- Существующий домен meetcalendar.fin-partner.pro и существующий российский VPS. Покупать новый домен или отдельный сервис размещения не требуется при достаточных ресурсах текущего VPS.
- Планируемый постоянный URL Mini App: https://meetcalendar.fin-partner.pro/app/. API того же сайта: /api/v1/. Это целевые адреса, пока не подтверждённые как работающие. Корень сайта и политика сохраняются.
- Текущие bot и worker сохраняются; добавляется HTTP API, nginx отдаёт собранный интерфейс и передаёт API-запросы. Внешний доступ к SQLite и внутреннему порту API не открывается.
- Bot/API/worker используют один общий слой правил и одну рабочую SQLite. Тестовые базы, посетители и заявки в рабочую базу не переносятся.
- Используется существующее подключение Google владельца из серверного .env. Посетителям не требуется подключать свои Google-аккаунты; email используется для приглашения. Проверка занятости, событие и отмена выполняются общим Google-клиентом.

## Что подготовить до рабочего изменения

1. Рабочий launcher API, читающий явные серверные настройки и использующий настоящий Google-клиент. Не снимать ограничения со старого тестового launcher и не публиковать owner-preview с имитацией календаря.
2. Проверяемые изменения Docker/Compose и nginx, сборку frontend и проверку readiness, права файлов, размер пулов и ограничения ресурсов.
3. План перехода рабочей схемы v8 к v11: резервная копия, согласованные версии bot/API/worker, миграция одним процессом, проверка сохранности записей и процедура восстановления.
4. Совместимость с auto-deploy: изменение инфраструктуры и миграций выполняется управляемо, защита auto_deploy не обходится. Перенос dev в main сам по себе не завершает размещение.
5. Актуальное состояние Google и синхронизацию времени на VPS; по согласованию одна настоящая контрольная встреча с тестовым email и её отмена.
6. Оставшиеся обязательные проверки MA-5: реальная доставка, сбои/восстановление, серверные ресурсы и нагрузка, необходимые условия обработки данных из существующего проекта.
7. Представить конкретный подготовленный diff/процедуру владельцу, затем получить предусмотренное исходным поручением отдельное разрешение на main и серверные действия.

## Открытие для участников домашнего задания

После серверной проверки настроить общую кнопку меню и Main App на постоянный HTTPS-адрес. Ссылка для участников: https://t.me/MyMeetPlanning_bot; прямая https://t.me/MyMeetPlanning_bot?startapp становится точкой входа только после включения Main App и проверки сценария первого посещения. Telegram поддерживает запуск основного приложения из профиля и по ссылке.

Убрать временное ограничение входа двумя тестовыми ID в рабочем API. Это не отменяет утверждённый ручной допуск к бронированию: любой Telegram-пользователь сможет открыть начальный экран и запросить доступ; после разрешения администратора увидит запись. Автоматический допуск всех участников или демонстрационный режим со слотами без допуска является отдельным изменением продуктовых правил. Для демонстрации участники пользуются ролью посетителя; административный интерфейс остаётся только владельцу.

Не использовать временный trycloudflare-адрес как постоянный адрес в BotFather. Новое размещение не должно зависеть от ноутбука. Ссылку в учебный чат публикует владелец; разрешения отправлять сообщения в учебный чат исполнителю не давалось.

Основание: ТЗ Mini App §13.2–13.4 и план MA-6. Telegram: https://core.telegram.org/bots/webapps#launching-the-main-mini-app; приглашения Calendar: https://developers.google.com/workspace/calendar/api/v3/reference/events/insert.
