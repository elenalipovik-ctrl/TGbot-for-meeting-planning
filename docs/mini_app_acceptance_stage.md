Дата: 11.10.2026. Ветка: dev. Статус: в работе; основные локальные проверки выполнены, внешний тестовый контур отсутствует. MA-6 не разрешён.

## Что принято владельцем

Владелец просмотрел и протестировал административный интерфейс, сообщил «Всё пока ок» и поручил следующий этап. Два существующих шаблона оставлены без изменений; возможность редактировать и добавлять шаблоны достаточна. Это принятие локального интерфейса, а не настоящего входа Telegram/Google/мобильных клиентов. Прежнее принятие интерфейса посетителя сохраняется.

## Изменения по результату проверки

1. Устранён MA5-01: отсутствовал серверный выключатель Mini App из ТЗ §13.4. ApiConfig.enabled и MINI_APP_ENABLED=true|false в изолированном запускателе управляют доступностью HTTP-методов. При false вход и команды получают безопасный 503 MINI_APP_DISABLED. Проверка повторяется перед записью, в том числе после подготовки Google-запроса. Уже закоммиченное намерение/начатый внешний вызов не откатывается выключателем; его завершает общий механизм восстановления. Диалоги и worker не зависят от флага. UI показывает сохранность записей, возврат в диалог через Telegram.WebApp.close при наличии SDK и повторную проверку доступности. В обычном браузере нужно вернуться в чат вручную. Нет HTTP-метода переключения и скрытого admin bypass.
2. Устранён MA5-02: настоящий тестовый запускатель отдавал только auth-check, без React UI. Параметр --frontend монтирует только mini_app/dist на /app/. Отсутствующая сборка, символьные ссылки и неожиданные/скрытые файлы отвергаются. Ответы имеют CSP, no-store, nosniff и no-referrer. /local-preview/session отсутствует; настоящему интерфейсу требуется проверенный Telegram-вход. Статика остаётся доступна при выключенном API, чтобы объяснить причину. Проверка в настоящем Telegram WebView с этим CSP ещё открыта.
3. Добавлены tests/test_mini_app_acceptance.py и scripts/check_mini_app_load.py. Новых бизнес-правил, категорий встреч и зависимостей не добавлено. Рабочая схема/данные не менялись.

## Доказательства локальной проверки

- HTTP → AdminFlow: подача через API, решение и видеоссылка через обработчик диалога администратора; один номер и одна встреча. VisitorFlow → HTTP: подача через диалог посетителя, решение и видеоссылка через API. Оба пути проверяют отмену, перезапуск API, обработку worker и отсутствие повторной отправки уже доставленных синтетических уведомлений. Сетевые Telegram/email не вызываются.
- Дополнительно проверены парные гонки approve/cancel и двух ссылок: один успешный переход, второй 409, одна Google-модель/встреча. Submit ровно на границе hold в конкуренции с worker не создаёт pending. Изменение допуска или закрытие интервала во время FreeBusy повторно проверяется перед commit, без успешной записи операции.
- Два отдельных процесса API/VisitorFlow конкурируют за одно время: одна активная бронь. SQL-проверка подтверждает результат, проигравший получает конфликт/сообщение о занятом времени.
- Все 29 административных HTTP-методов проверены корректными входными моделями: посетитель получает 403, запрос без сессии - 401; нет Google-вызовов/бизнес-записей. Невалидное тело не используется для маскировки отсутствующей проверки прав.
- SQLite удерживается другим писателем: безопасный 503 STORAGE_BUSY / Retry-After: 2, нет частичного шаблона/операции, тот же запрос после снятия блокировки успешен.
- На синтетической v8 сделан снимок SQLite backup API, выполнены v8 → v11 и повторный старт, проверены старый снимок заявки, integrity_check, foreign_key_check; старый код v8 отвергает v11. Восстановление снимка возвращает v8 и исходные строки. Сбой DDL v11 оставляет v10 без половины новой таблицы; повтор успешен. Это не снимок рабочей базы.
- Выключенный API не мешает AdminFlow согласовать встречу, VisitorFlow запросить отмену, worker завершить её; включение API возвращает прежнюю сессию/данные. Отдельно проверено выключение после подготовки, до записи hold.
- Изолированная страница на временном порту 8767 показала «Продолжим в чате»; повторная проверка доступности выполняет новый запрос и оставляет понятное сообщение. Скриншот: mini_app_disabled_preview.jpg. Встроенная кнопка close SDK требует WebView и здесь не проверялась. Временный сервер остановлен; основной локальный просмотр 8766 работает.

Регрессия после изменений кода: 198 passed, 1 skipped, 1 warning in 87.46s. Затем добавлены и отдельно пройдены ещё 5 проверок обязательных конкурентных переходов (5 passed in 6.25s); итоговое покрытие текущего набора - 203 прошедших проверки и 1 пропуск. frontend 4 passed, TypeScript/Vite, OpenAPI --check, generated types --check, compileall, pip check прошли. Существующий Starlette TestClient предупреждает о будущем переходе httpx → httpx2; это предупреждение тестовой среды, не ошибка рабочего HTTP API. На Windows пропущена проверка POSIX permissions auto-deploy: она должна выполняться в Linux CI.

## Локальная нагрузка

Машиночитаемый результат: [mini_app_load_local.json](mini_app_load_local.json). Исполнитель запускает .venv/Scripts/python.exe -X utf8 scripts/check_mini_app_load.py --seconds 60 --report docs/mini_app_load_local.json.

Двадцать независимых HTTP-сессий, 60 секунд, каждый клиент сначала пытается занять один общий слот, затем читает bootstrap/шаблоны/свои заявки/профиль примерно каждые 2 секунды. Подписи/auth имеют отдельные тесты; для измерения бизнес-API синтетические сессии выданы заранее, чтобы не отключать общий лимит входа 10/мин/IP. Лимиты чтения/команд не повышены. Общая временная WAL SQLite, in-process Uvicorn на случайном loopback-порту, управляемый календарь без сети. Параллельно раз в секунду вызываются реальный worker и VisitorFlow.menu. Сборщик закрывает сервер/дескрипторы и удаляет только собственный временный каталог.

Финальный диагностический прогон: 590 чтений, все 200; одна успешная бронь и 19 ожидаемых 409. Чтение p50 27.21 мс, p95 189.38 мс, максимум 553.33 мс. Пакет конкурирующих записей p95 1263.72 мс измеряется отдельно от чтения. Worker: 58 циклов, p95 24.37 мс; чат: 58 циклов, p95 43.01 мс. Ошибок фоновых обработчиков нет, пересекающихся броней нет, integrity=ok, foreign_key_violations=0. CPU процесса 13.33 с / 60.02 с (около 0.22 одного ядра); максимум наблюдаемой RSS процесса около 200 МиБ. Это общий процесс теста, API, клиентов и фоновых потоков, не отдельный контейнер API. Максимум временных файлов 943729 байт, журнала 278296 байт.

Первый прогон одновременно с полной регрессией дал p95 чтения 619.05 мс; в нём счётчик памяти Windows был недоступен. Исправлен тип HANDLE и повторён измеряемый прогон выше. Значения зависят от нагрузки ноутбука.

Это НЕ закрывает D-08/T-33: продолжительность 15 минут, реальные ресурсы VPS, Google, браузерные 200 мс/3 с, сеть 10 Мбит/с и RTT 100 мс не проверены. Скрипт поддерживает --seconds 900, но запуск на VPS и условия нагрузки отдельно согласуются. Достаточность 1 ядра/1 ГБ/10 ГБ не заявляется. Полный профиль/конкурентное окружение и допустимый возраст фоновых заданий нужно зафиксировать перед измерением.
