# Mini App: инструкция тестового запуска и восстановления

Дата: 11.10.2026. Подготовлено в dev для MA-5. Команды предназначены исполнителю. Владелец проверяет интерфейс по готовой ссылке. Ничего из раздела внешнего контура пока не запускалось.

## Что можно делать сейчас

Локальный интерфейс: http://127.0.0.1:8766/app/, администратор: http://127.0.0.1:8766/app/?persona=admin. Только этот ноутбук, вымышленные данные, отдельная .secrets/miniapp-preview/test-v2.sqlite. Google/Telegram/email не отправляются. Не выставлять этот процесс в сеть/туннель: у него специальный вход по персонам. Для настоящего теста используется другой запускатель ниже.

Для шаблонов: добавить шаблон, изменить название/описание/инструкцию, скрыть или снова показать. Старые заявки сохраняют свой снимок. Владелец решил пока оставить «Знакомство и обсуждение задачи» и «Рабочая консультация»; новые категории не добавлены.

В обычной работе: при непонятном результате обновить карточку, сообщить номер заявки и номер запроса из ошибки. Повтор той же команды использует прежний ключ; не нужно создавать другую заявку, чтобы проверить ответ. При проверке Google смотреть checked_at и сообщение о тестовом адаптере. Одобрение без видеоссылки ещё не подтверждает встречу.

## Что требуется для настоящего теста

1. Владелец через свой Telegram создаёт отдельного бота в @BotFather (/newbot) и сообщает только username. Токен не присылать в чат; сохранить только локально в .env-miniapp-test по docs/mini_app_test.env.example. Рабочий @MyMeetPlanning_bot запрещён запускателем. Назначить BOT_ADMIN_ID владельца; для сквозного теста нужен второй настоящий аккаунт.
2. Исполнитель и владелец выбирают HTTPS-адрес/способ изоляции. /app/, /auth-check и /api/v1/ должны быть на одном origin с валидным сертификатом. Прокси направляет только эти публичные пути к тестовому loopback API; .env/.secrets/база/логи/исходники не публикуются. Рабочий VPS/домен не меняются без отдельного разрешения. Локальный preview не используется в этом маршруте.
3. До доступа извне проверить доверенный proxy/IP. Текущий запускатель proxy_headers=False: forwarded-заголовки клиента не доверенные, лимит входа за прокси общий. Нельзя просто включить доверие ко всем X-Forwarded-For. Настройка точного доверенного адреса/передачи peer и антиспуфинг ещё открыты.
4. Собрать интерфейс и запустить изолированный API после заполнения локального файла:

~~~powershell
.\.venv\Scripts\python.exe -m pip install -e '.[test,api]'
# В mini_app: pnpm install --frozen-lockfile --ignore-scripts; pnpm build
.\.venv\Scripts\python.exe -m meeting_bot.api --env-file .env-miniapp-test --port 8765 --frontend
~~~

Параметр --frontend отдаёт только собранный mini_app/dist. Без него остаётся диагностический auth-check. Запускатель проверяет getMe отдельного бота, использует фиксированные .secrets/miniapp-test/test.sqlite и api.log возле test env, не читает рабочий .env, не запускает polling/worker. Подделка persona/devTelegramId не поддерживается. Секреты не помещаются в frontend-сборку.

5. Только у тестового бота настроить кнопку на https://TEST_HOST/app/. До этого проверить извне сертификат, пути, отсутствие секретных файлов, CSP/SDK, безопасные журналы и выключатель. Затем проверить свежий вход администратора и другого аккаунта, запрос/разрешение доступа, блокировку при открытом приложении, переоткрытие, истечение/отзыв. Результаты записать без bearer/initData.
6. Для бронирования настроить отдельный Google-календарь, MINI_APP_CALENDAR_IS_TEST=true, тестовые OAuth credentials и тестовый email. primary и рабочий календарь запрещены. Без Google auth можно проверять, но календарные действия получают unavailable. Перед созданием события исполнитель проверяет календарь, время/зону и адрес приглашения.
7. Настоящие тестовые polling/worker/Telegram-транспорт ещё требуют отдельного изолированного запуска с этой же базой и allowlist тестовых получателей. Запускать нынешний рабочий процесс с рабочим .env нельзя. Текущие автоматические тесты внедряют транспорт без отправки людям; это не доказательство настоящей доставки. До выполнения этого пункта T-22/T-23/T-30/T-35 остаются частичными.
8. Пройти ТЗ §12.2: посетитель → разрешение в чате → подача → административный UI → одна Google-встреча/письмо/сообщение → отмена из чата → отсутствие события/единый статус. Повторить Android/iOS/Desktop/Web в согласованном объёме; записать платформы, темы, клавиатуру/safe area и ограничения.

## Отключение Mini App

У изолированного тестового API MINI_APP_ENABLED=false в его test env и перезапуск только API закрывают новые входы/HTTP-команды с безопасным 503. Не редактировать рабочий .env. Процесс оператора также может выставить app.state.mini_app_enabled=False; публичного маршрута для этого нет. Возврат true и перезапуск сохраняют данные/сессии с учётом их TTL.

Закоммиченные заявки и Google-намерения не удаляются. Совместимые bot/worker продолжают работу и восстановление внешних операций. Транзакция проверяет флаг перед записью; уже принятый внешний вызов может закончиться после выключения. Остановка/убийство worker ради отключения UI не является процедурой восстановления.

Рабочий запускатель API/Compose, feature flag в production и управление сервисом ещё относятся к MA-6. Нынешняя команда meeting_bot.api является только тестовой и не должна адаптироваться под рабочий токен снятием предохранителей.

## Матрица схемы и восстановление

| Схема базы | Допустимый комплект | Ограничение |
|---|---|---|
| v8 | Прежний рабочий bot/worker | Новый API требует явной миграции; рабочая база остаётся v8 |
| v9/v10 | Соответствующий исторический код общего слоя/API | Текущий API v11 не запускается на несовпадающей схеме |
| v11 | Текущий согласованный комплект bot/API/worker из dev | Старый код v8/v9/v10 запускать нельзя |

Рабочая миграция не разрешена. Для MA-6 подготовить отдельный конкретный diff, ID версии, окно остановки несовместимых писателей и согласованный снимок. Автоматический deploy main не должен сам применять инфраструктуру/миграции в обход своих ограничений.

Репетиция на синтетической базе: через SQLite backup API сохранить снимок, проверить schema/integrity/foreign_keys и контрольные строки, применить текущие миграции, повторить старт и проверки. При сбое отдельной миграции транзакция этой миграции откатывается; предыдущие успешные версии остаются (например, сбой v11 оставляет v10, а не возвращает v8). Восстановить снимок backup API только после закрытия всех соединений/писателей, затем запустить комплект, совместимый со схемой снимка. Не копировать отдельно открытый sqlite без WAL.

Восстановление старого снимка теряет записи после его создания. Поэтому сначала выключить Mini App, сохранить совместимые bot/worker и исправить вперёд, если это возможно. Статику возвращать только к версии, совместимой с API. Никогда не подменять рабочую SQLite молча. Новые данные/события Google необходимо сверить до выбора восстановления.

## Контроль данных и правовой зависимости

Добавлены технические сущности: общий черновик/revision, хеши сессий и входов, rate-limit buckets, HMAC-реестр команд/ссылки на результат, Google check status/checked_at, настройка начал. Контакты/снимки/согласия остаются общими с ботом. Полный Telegram user JSON и initData не сохраняются; bearer только в памяти клиента, SHA-256 на сервере. TTL: initData 5 минут, сессия 30 минут, операции 24 часа; очистка общим worker. Эти сроки не заменяют общие правила хранения персональных данных действующего продукта.

До настоящих данных/релиза сверить действующую политику и открытые правовые пункты этапов 6–7 бота с новым способом доступа: веб-интерфейс, HTTPS/хостинг, Telegram-auth и выбранный Google-поток. Новая юридическая оценка здесь не выполнена, согласие пользователя/уведомление оператора автоматически не объявлены достаточными. Никаких новых контактов/аналитики/трекеров/платных сервисов не добавлено.
