Записи и пользователи вымышленные; Google/email/Telegram не отправляются. Для переключения роли есть панель локальной проверки; в настоящем приложении роль определяется сервером по Telegram ID. Production factory не принимает тестовую персону.

1. «Заявки на решение»: открыть ожидающую заявку, согласовать, добавить ссылку выбранной платформы, проверить подтверждение. Для теста пригодны https://zoom.us/j/123456789 или https://telemost.yandex.ru/j/ma4-demo (это не реальные созвоны).
2. «Пользователи»: посмотреть запросы/разрешённых/заблокированных и подтверждение изменения прав. Проверка исполнителя уже разрешила pending_preview; запрос можно создать из сценария «Без доступа».
3. «Расписание встреч»: посмотреть пять начал, интервалы, предварительные последствия закрытия и фактический результат. Среда/выходные открываются только явным исключением на конкретную дату.
4. «Шаблоны встреч»: изменить описание/инструкции или скрыть шаблон; ранее поданные заявки сохраняют свои снимки.
5. «Часы рассмотрения»: посмотреть/изменить окна, проверить пример срока. Это часы ответа, отдельные от расписания встреч; существующие сроки не пересчитываются.
6. «Подключение Google», «Сводка», «Предупреждения»: проверить отдельный статус, дату проверки, периоды 7/30 дней и переходы к проблемным заявкам.

## Реализация

AdminPanel.tsx: меню A-01–A-13, серверная пагинация, фильтры даты/статуса, решения с CAS, видеоссылки, повтор календаря, отмена с ожиданием результата, подтверждения опасных изменений, просмотр предварительных и фактических последствий, интервалы/блокировки, шаблоны, окна, пример срока, сводка/предупреждения. Роль и допустимые действия проверяются API. Чувствительные поля не записываются в браузерное хранилище, логи или URL.

Административная очередь отделена от собственных заявок администратора. Ожидающие сортируются сервером по сроку, затем ID до пагинации. Кнопка Google открывает Google-раздел; секреты/OAuth в UI не вводятся. В preview явно указан тестовый адаптер, успешная проверка не означает подключение настоящего Google.

Добавлены GET/PUT /api/v1/admin/start-options (revision, minutes), POST /api/v1/admin/review-schedule/preview (те же окна, без сохранения), ссылки на заявки с ошибками доставки и число заявок без видеоссылки в /admin/alerts. Контракт и генерируемые типы обновлены.

## Общие начала и миграция v11

011_booking_start_options.sql хранит допустимые минуты и ревизию общей настройки. При миграции список пуст: сохраняется прежний шаг 15 минут, данные/бронирования не переписываются. Локальный launcher один раз применяет принятые 630,690,810,900,990 минут (10:30,11:30,13:30,15:00,16:30), далее сохраняет изменения администратора.

BookingService фильтрует результаты существующего available_slots и повторно проверяет разрешённое начало внутри транзакции create_hold. Поэтому чат и API используют одну настройку; прямой запрос на непредлагаемое начало отклоняется. Уже удержанные/поданные заявки сохраняются. Предыдущая локальная PreviewService с собственным фильтром удалена. Настройка не публикует даты и не меняет занятость, буферы, длительности, lead time или дни работы. Окончание до 18:00 обеспечивается опубликованным интервалом; форма предлагает обычные интервалы 10:30-18:00.

Миграция проверена только на временной/локальной базе. Код v10 с базой v11 несовместим и не должен запускаться против неё; отключение Mini App не отменяет необходимость совместимой версии бота/worker. Рабочий переход main/VPS и восстановление остаются MA-6, без разрешения не выполнялись.
